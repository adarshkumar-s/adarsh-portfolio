Anshika Studio

A secure studio/boutique web application with a public catalogue and a protected administration workflow. The details below come directly from the connected Anshika_studio repository.

STACKFastAPI · SQLAlchemy · Pydantic · PostgreSQL / SQLite
AUTHServer-side sessions · Argon2 password hashing · CSRF
ADMINProducts · enquiries · dashboard · audit trail · image uploads

Overview

The repository describes “Label by Anshika — Secure Studio” and implements a public product catalogue, enquiry flow and private admin control room.

Problem / purpose

The application provides a central place to publish collection pieces, receive product enquiries and manage catalogue content through an authenticated studio interface.

Architecture

FastAPI serves HTML templates and static assets. SQLAlchemy models users, sessions, products, enquiries, settings and audit logs. The README recommends PostgreSQL for production while SQLite is supported for local development.

Authentication & security

  • Server-side session tokens are stored as SHA-256 hashes.
  • Passwords are verified with Argon2.
  • Administrative mutations require a CSRF token.
  • Failed logins trigger temporary account lockout after repeated failures.
  • Security headers include CSP, HSTS in production, X-Content-Type-Options, X-Frame-Options and a restrictive Permissions-Policy.
  • Audit entries hash IP addresses rather than storing raw addresses.

Database

SQLAlchemy supports PostgreSQL or SQLite. The schema includes users, sessions, products, enquiries, settings and audit logs.

Admin functionality

The protected admin surface supports product creation, updates and archiving, enquiry status changes, dashboard counts and audit-log inspection.

Image / file handling

Product images accept JPEG, PNG, WebP or AVIF, are size-limited, checked with Pillow and saved under generated server-side filenames. The production checklist calls for persistent/object storage rather than an ephemeral filesystem.

Deployment

The repository includes a Dockerfile and explicitly recommends PostgreSQL, HTTPS, a reverse proxy, secure secrets, backups and persistent/object storage for production. No deployed public URL was verified in the repository, so none is presented as a live demo here.

Engineering decisions

The project keeps secrets in environment variables, disables FastAPI docs in production, separates public and admin APIs, uses typed request validation and records sensitive administrative changes.

Tests

The repository contains tests/test_security.py, covering security-oriented application behavior. This portfolio does not copy or claim results from that test suite without executing it.
